# 性能与资源占用

## 为什么迷你窗口仍有约 129MB

迷你模式只改变窗口显示内容。Python 解释器、Qt Widgets、字体、托盘、网络与行情订阅仍在同一个进程中运行；窗口高度与进程内存不成比例。优化前，默认启动还会导入工作台全部页面并启动其独立行情、K 线和衍生品服务。

工作台关闭仍然是隐藏，已打开的页面和未保存草稿继续存在。不能只根据一次任务管理器截图判断内存泄漏，也不能期待隐藏窗口立即回到首次迷你启动时的内存。

## 2026-09-26 的启动与发行优化

- 工作台和旧设置窗口延迟导入。没有账户、没有启用提醒的首次迷你启动不启动工作台行情；已配置的账户、本地模拟及启用的提醒仍会恢复监控。打开工作台启动服务，重复打开不重复初始化订阅。
- Bar Replay、策略回测按首次访问创建，避免仅看盘时提前创建这些控件和历史缓存连接；创建后继续保留训练状态与草稿。
- 行情缓存最多保留 8 个闲置合约／周期组合。当前选择、多图、跨周期指标、启用的提醒、在途请求与补缺任务的数据受到保护。闲置组合的原始数据、数值序列、指标及索引一起淘汰，不删除交易记录。活跃组合的内存窗口规则见下文 2026-09-29 改造。
- 历史缺口查询只读取时间戳索引；历史读取不再先复制全部 JSON 查询结果；缓存写入使用生成器与紧凑 JSON，减少临时对象和新增缓存体积。
- 相同订单轮询结果不再重复写入订单及状态标记，减少 SQLite 写事务与 WAL 写入。
- Windows 分发移除未用到的软件 OpenGL、PDF 及部分图片插件、非中文翻译、项目展示图片和重复 ICO 源帧；保留运行需要的合并图标、字体、许可、中文翻译与 Windows TLS 后端。发行脚本的必需资源检查同步调整。
- 安装器升级阶段清理对应旧资源，防止覆盖安装后残留旧文件抵消体积优化；不清理用户配置、数据库、凭据或图标缓存。

未自动删除开发环境、旧构建包、用户历史缓存或业务记录。已有 SQLite 文件不会因新记录使用紧凑 JSON 而立即整体缩小。8 个闲置组合是数量上限，不是总字节上限；用户记录和回测交易结果仍会占用资源；研究历史的分页改造见下文。

## 2026-09-29 的完整行情数据管线

《优化建议.md》中的八项改造均已接入生产调用路径，继续使用 QPainter。行情采用新接口与独立的 `.candles-v2.sqlite3` 缓存，不迁移旧 JSON K 线库，也不保留字符串行、展开全部缺口或无状态增量指标接口。旧缓存文件不会被自动删除。

| 优化项 | 当前实现 |
| --- | --- |
| 磁盘全量、内存窗口 | 原始历史存入 SQLite，每组合默认保留 16,000 根，包括最近 6,000 根及各图窗独立登记的可见区间；必需视口总量超过预算时按实际需求扩展，批量腾出增长空间 |
| 主图复用磁盘缓存 | 启动、历史分页及日期跳转先读本地，缺失部分再调用异步 REST；历史加载器直接从缺口分页 |
| SQLite 数值列 | `WITHOUT ROWID` 数值 K 线表、已收盘覆盖区间表、多周期聚合表；REAL 存储 OHLC 与成交量，价格计算仍遵循双精度行情精度 |
| 列式数值内存 | int64 时间、七列 float64、uint8 确认标记，共 65 字节有效载荷／根；时间和 OHLCV 视图复用列，索引使用二分查找；指标结果同样使用数值数组 |
| 全指标增量 | EMA、RSI、MACD、ATR、Supertrend、VWAP 保留递归状态；MA、成交量均线、BOLL 使用可回退滚动统计，Stochastic 使用单调队列；末根修正回退一步，缺口及历史中未收盘记录后重新预热 |
| LOD 与多周期金字塔 | 数值缓存写入时维护更大周期的 OHLC 极值及成交量；只将完整、连续、已收盘桶作为已确认聚合。跨度较大时自动选择显示周期，稠密蜡烛再按像素合并；主图状态显示所用周期，图表周期指标按显示周期计算 |
| 后台 I/O 与计算 | 历史查询、写入、分页快照、大范围序列转换和指标重建在工作线程进行；Qt 线程发布完整结果，版本与取消标记拦截过期响应。SQLite 连接按线程创建，退出前收拢任务后统一关闭 |
| Pixmap 平移复用 | 数据、价格范围、成交量尺度及缩放未变，且位移为整数设备像素时滚动缓存，只清理并补绘暴露条带；其他情况完整重建；轴与标签独立绘制 |

默认单图可从 15 根缩放到 5,256,000 个基础周期单位。例如分钟图可查看约十年的跨度，实际显示更大周期的蜡烛；可获取历史仍取决于本地数据及数据源覆盖。聚合不会跨越缺口，也不把缺失值补成零。日线按 OKX UTC+8 的日界线维护。

提醒和扫描复用共享指标状态，异步结果尚未准备好时保持“未知”，不会提前触发。相同参数每组合最多缓存 32 个状态。连续前缀滚出时保留递归种子；历史插入、更早修正、非连续窗口或参数变化在后台重建。金额、手续费、风险预算和合约张数继续使用 Decimal。

回放与回测通过固定宽度磁盘快照和最多两页缓存访问历史。回放交易窗口保留最近最多 6,000 根，旧视口及 LOD 在后台从快照读取，聚合严格截止当前游标；回放不借用实时跨周期序列。回测逐根推进指标，在已收盘信号之后的下一根开盘撮合，支持取消；权益曲线按时间桶保留首尾及极值，最多约 4,096 个展示点，最大回撤仍按每一根精确累计。交易明细属于回测结果，仍完整保留，其内存与实际成交笔数有关。
